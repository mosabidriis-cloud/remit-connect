## RESOLVED - REOS page mounting (Sprint 14)

A critical defect found during Sprint 14 Milestone 2B: the application's real router `src/routes/AppRoutes.tsx` never mounted `BranchProcessingPage`, `SharedBatchUploadPage`, `BranchAssignmentPage`, `TransactionProcessingPage`, or `ReportsPage`, while `src/features/reos/routes/ReosRoutes.tsx` defined them as dead code nothing imported. Those pages therefore did not ship, despite compiling and building cleanly.

Resolved by the Sprint 14 Route Integration Audit (five routes mounted in the live router) and Stabilization & Closure (`ReosRoutes.tsx` deleted). Verified against the production bundle at the time: previously-absent page strings were present.

Sprint 15 M1 went further and verified this by actually using the app in a browser (upload, assign, navigate) rather than inspecting the bundle - confirming the fix holds for a real user journey, not just that the code is present. Sprint 15 also found (M1) and fixed (M1.5, M1.75) two further defects that bundle-content and `tsc`/`build` checks alone could not have caught: a missing navigation link, and a data-corrupting hydration bug.

Lesson recorded in PROJECT_STATE.md as a standing caveat - a passing build does not prove changed code ships, is reachable, or preserves data correctly.
