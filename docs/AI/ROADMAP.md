## Upcoming

- **Build an automated, CI-integrated regression suite** - the single largest remaining gap. Every verification across all five Production Readiness phases has been a hand-written, ephemeral script (Playwright or direct Supabase API calls), run once against the live dev server and real project, then deleted. Proves correctness at the moment of checking, not against future changes. Choosing a runner, deciding what stays mocked vs. hits real Supabase, and wiring it into CI is a distinct, larger body of work from verifying the product milestone by milestone.
- **Resolve the `USER_CREATED` audit persistence gap** (TECH_DEBT.md, "Audit Trail") - root cause not fully isolated despite investigation; needs a persistent, non-console diagnostic the next time this module is touched.
- **Bundle-size code-splitting** (`vite build`'s "chunk larger than 500 kB" warning) - deliberately deferred in Phase 4 as a larger, more invasive change than that pass's scope; no demonstrated cold-load problem for an internal ops tool today.
- **Build the Audit report category** (Assignment History, Lifecycle History, Processing History, Proof Download History, User Activity) - the underlying data now exists (Phase 3); the report definitions themselves are separate, downstream Reporting work.
- **Multi-source ingestion** (Western Union, RIA, MoneyGram, TerraPay) - explicitly out of scope for Import Intelligence (confirmed by user decision, 2026-08-08); no parser exists yet for any of their file formats.
- **Branch comparison in Historical Performance** - not built; the Import Ledger has no branch dimension today, since branch assignment happens after import in the live workflow. Would need a schema decision. See IMPORT_INTELLIGENCE.md Section 13.
- **New Performance report definitions** (`PROCESSING_TIME`, `OFFICER_PERFORMANCE`'s speed component) - the data now exists (Decision D-6), the report definitions do not yet.
- **Reconcile the legacy Treasury/Branch Liquidity/Funding system** (`src/pages/branches`, `treasury`, `funding` - outside REOS) with the new Liquidity Management module. Both now exist; LIQUIDITY_MANAGEMENT.md Section 3 records why they were kept separate, but no decision has been made on the legacy system's long-term status. See TECH_DEBT.md.
- Carried forward, per TECH_DEBT.md: the `payout_accounts` INSERT policy broader than the UI's own intent (a Postgres upsert-mechanics constraint, DEC-021); no admin password-reset UI; the orphaned `proofOfPaymentService.markProofDownloaded`; proof expiry not enforced against `expiresAt`; the `branch_processing_status` one-way lock with no reset path (DEC-020); the Sidebar's remaining placeholder links (Proof Download, User Details/Edit - the dead "Transaction Processing" link was removed along with the page it pointed to, DEC-020); removal of out-of-scope financial metrics from the Operations Dashboard (Decision D-9); a React Hooks lint cleanup (`set-state-in-render`/`set-state-in-effect`), still spanning Sprint 13-16 code, `npm run lint` still not clean project-wide.
